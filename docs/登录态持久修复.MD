# 修复:每次启动都要重新扫码登录(登录态不持久)

> 适用:Electron 版微信开发者工具(2.02.2608070 及同源构建)以 AppImage 方式在 Linux 运行时的问题。
> 2026-09-14 在 Ubuntu 24.04 上实测闭环:修复后完全退出再启动**无需重新扫码**。

## 症状

- 每次启动工具都弹出扫码登录页,必须重新扫码;
- 扫码登录一次后,userData 下多出一个 `xxxx…(32位hex)` 目录,体积约 300MB;
- 全部历史数据(项目列表、登录态)每次都在"新目录"里重建,旧目录成为孤儿垃圾。

## 根因(AppImage 特有)

工具把"数据目录"hash 为应用路径的 md5:

```js
// 数据目录 = <userData>/<md5(应用路径)>
dataPath = join(app.getPath("userData"), md5(baseAppPath))
```

`baseAppPath = app.getAppPath()` 在 **AppImage 里每次启动都指向随机的挂载点**
`/tmp/.mount_XXXX/resources/app`,md5 值随之变化,**每次启动都得到一个全新的空数据目录**:

- 上次登录写入的登录态(<数据目录>/WeappLocalData/ls_<md5("userInfo")>.json,
  含签名票据;与 ls_encrypt_secret.json 密钥文件成对)在新目录里不存在;
- 启动时 `IGlobalStoreService.get("userInfo")` → LocalStorageService 读取该文件 →
  为空 → isLogin 判定未登录 → 弹扫码页。

数据目录 hash 由**两处独立代码**产生,都会导致漂移,需一并修复:

| 文件 | 函数 | 影响 |
| --- | --- | --- |
| `js/bd3919eb5ba5af9000b9c9b25a078747.js` | `getDataPathSync()` | 登录态/项目数据(LocalStorageService / AppDirService / 日志)所在目录 |
| `js/c47addee36149e53772b60ab7e158ffe.js` | `bootstrapAppPaths` → `getDataDirHash()` | bootstrap 数据根 / 热更新(WeappCode)/ NW 兼容层 |

Windows/常规安装在固定目录,`app.getAppPath()` 不变,所以官方没有此问题。

## 修复方案

把两处 hash 的输入从动态 `appPath` 改为固定值:

```js
md5("wechat-devtools-linux::" + app.getName())   // app.getName() = "wechat-devtools"
```

修复后数据目录固定为 `md5("wechat-devtools-linux::wechat-devtools")`
= `7770ddceae245fa2beb78d8d10454c32`(位于 `~/.config/wechat-devtools/` 下),
登录态与项目数据天然持久。

- 需要隔离/覆盖时可设环境变量 `WECHAT_DEVTOOLS_DATA_HASH=<32位hex>`(两处补丁都支持)。
- 补丁保留 `isDev()` 分支(开发态 hash 固定 `1111…`),不影响热更新版本回退逻辑。

## 构建集成

`tools/fix-login-persist.sh` 在构建流程里打补丁,两种模式:

- **目录模式(主)**—— 构建树存在 `resources/app/js`(AppImage 解包/构建产物):
  直接修改 `resources/app/js/bd3919eb…` 与 `js/c47addee…` 两个文件。
  该目录即 Linux launcher(`bin/wechat-devtools`)实际加载的代码树。
- **asar 模式(兜底)**—— 仅有 `resources/app.asar`:
  用内置解析器(asar v4 JSON header)从 asar 提取原始文件 → 改后写入
  `resources/app.asar.unpacked/js/` 同名覆盖(Electron require 优先读取 unpacked),
  无需重打 asar。asar 与目录为不同构建批次时(同名 hash 内容不同)会给出警告并跳过,
  以目录模式为准。

幂等:已含补丁标记(`wechat-devtools-linux::`)则跳过;`--force` 强制重试。

## 存量数据迁移(升级用户一次性操作)

若已有账号数据/登录态散落在旧 hash 目录(如 `<userData>/<旧hash>/WeappLocalData`),
找到最近一次登录对应的目录(含 `ls_49f290d6…json` 且 mtime 为登录时刻的),
把它整体复制到新固定目录:

```bash
NEW=~/.config/wechat-devtools/7770ddceae245fa2beb78d8d10454c32
OLD=~/.config/wechat-devtools/<旧hash>            # 含 ls_49f290d6e8459c53f31f97de37921086.json
mkdir -p "$NEW"
cp -a "$OLD/WeappLocalData" "$NEW/"
```

之后启动即是已登录状态。旧 hash 目录(与登录态无关的缓存副本)可定期清理。

## 验证记录(2026-09-14)

1. 修复前:每次启动新建随机 hash 目录,登录态不可达,必扫码;
2. 修复包(目录模式 + 双文件 patch):启动后数据目录固定 `7770ddce…`,
   登录态文件就位,直接进入主界面(已登录);
3. 完全退出 → 再次启动 → 仍直接进入主界面,免扫码 ✅(闭环通过)。
